Boost.Beast 本地 HTTP 服务搭建记录

发布于 2026-04-24 阅读 128 约 6 分钟

这篇文章用一个轻量的本地服务做例子，把 C++、Boost.Beast 和静态前端文件串起来。目标不是把所有细节一次写满，而是先搭出一个可以访问、可以继续扩展的个人博客原型。

服务端负责什么

当前服务端只做三件事：监听端口、解析 HTTP 请求、从 web 目录读取静态文件并返回。这样的职责边界很清楚，后续想增加路由、接口或者缓存策略时，也能沿着已有结构继续生长。

实现重点

把页面资源保持为独立文件，可以让前端调样式和交互时不需要重新编译 C++ 项目，刷新浏览器就能看到结果。

前端页面的组织

首页使用文章卡片承载入口，详情页则切换成更安静的阅读布局：顶部是沉浸式标题区，中间是正文内容，右侧放目录和作者信息。这种结构更接近独立博客文章页，阅读节奏也更舒服。

GET /article.html?id=1
GET /styles.css
GET /app.js

可以继续补的交互

目前已经有阅读进度条、返回顶部和文章卡片点击跳转。下一步可以加入评论、目录高亮、文章搜索，或者把文章内容从 JSON 文件中动态读取出来。
